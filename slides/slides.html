How Many Bytes Does Encrypted Traffic Classification Actually Need?

Observation Budgets, Padding Effects, and an Adaptive Early-Exit Classifier for Raw-Byte Traffic

The problem

Every deep traffic classifier reads a prefix. Nobody measures it.

2

A raw-byte classifier does not see a flow. It sees the first B bytes of it, zero-padded to a fixed length. That prefix is the observation budget.

The budget is not a tuning knob on the side. It is the operating point of the system:

  • Detection latency. A 1024-byte budget cannot decide before 1024 bytes have arrived.
  • Memory per flow. A middlebox holding B bytes for every concurrent flow scales linearly in B.
  • How early you can act. Blocking, shaping or alerting all wait on the same prefix.
What the field does instead

We reviewed 12 studies published in 2025 and 2026. The budget ranges from 5 to 20 packets, or 784 to 1024 bytes.

In not one of them is it measured. Where a reason is given at all it is architectural, such as a byte count that reshapes into a square image, not empirical.

The problem

Worse: budget and padding cannot be separated by construction

3

Network flows are short and heavy-tailed. The median ISCX VPN-nonVPN session is 274 bytes; the median USTC-TFC2016 session is 474 bytes. A budget larger than that does not read more traffic. It reads more padding.

So raising the budget raises the padding fraction, always. Any reported accuracy gain from a larger budget is a mixture of two effects: more real bytes, and more padding for the model to exploit as a length cue.

No published result separates them. A study that reports “1024 bytes works best” may have measured a length classifier and called it a payload classifier.

This is the second thing we set out to decompose.

Research gap

Four gaps in the literature, addressed in order

4
Gap 1 · the budget is inherited, not measured No study reports accuracy as a function of the budget with the corpus, split, model and seeds held fixed. The budget is copied from an earlier paper, which copied it from an earlier one.
Gap 2 · aggregate accuracy conceals per-class failure P10 reports 97.65% overall but 92.20% on VoIP. P2 reports 88.61% overall with AIM at 0%. A single headline number cannot show which classes the model has given up on.
Gap 3 · “encrypted” is asserted, not measured P5 finds much of these benchmarks is not encrypted at all. Downstream work inherits the label without quantifying it, so the task being measured is not the task being claimed.
Gap 4 · shortcut learning is rarely excluded P5 shows that retaining identifier fields such as IP addresses and ports is worth up to 0.45 accuracy. Several studies do not state whether those bytes were removed.

Read together, these four gaps mean published budgets cannot be compared and cannot be trusted as evidence about how much of a flow a classifier needs. The contribution of this work is to measure, on two public corpora, what the field has assumed.

Objectives

Five questions, each with a measurable answer

5
  • O1. Measure the budget response. Accuracy as a function of byte and packet budget on two corpora, with everything else fixed, and locate the saturation budget: the smallest budget beyond which no larger budget is reliably better.
  • O2. Test whether the answer is a property of the model. Repeat the sweep with a second, structurally different architecture on the same store, split and seeds.
  • O3. Decompose the padding effect. Separate the gain from the input representation from the gain from the explicit PAD symbol, which the literature changes together.
  • O4. Build a classifier that reads only what it needs. An early-exit model whose per-flow byte cost is adaptive, with a causality guarantee so that “bytes read” is a real cost rather than a claim.
  • O5. Report honestly. Exclude shortcut learning with a gate that halts the pipeline, report per-class behaviour, and quantify how much of a published number is explained by the train/test split alone.

Methodology

One preprocessing pass, many budgets

6
Capture parsing, sessionization and anonymisation run once. Only the dashed region repeats per budget.

The design requirement. If the budget is to be a measured variable, it must be the only thing that changes between two points on the curve.

  • A single pass writes a fixed 2048-byte HDF5 session store, which is then sliced per budget.
  • Sessionization, deduplication, anonymisation and class balance are therefore identical at every budget. They cannot drift.
  • Splits are group-wise by capture file where the corpus allows it, so no capture appears on both sides of the boundary.
  • Every point is three seeds, reported as mean and standard deviation, never a single run.

Methodology

The leakage gate: a halt condition, not a caveat

7

Gap 4 is usually handled with a sentence promising identifiers were removed. We made it a precondition the pipeline enforces. Three probes are trained on byte positions alone, and the run stops unless the identifier probe is no better than guessing:

A(gID)  ≤  maxc πc + δ,    δ = 0.1

probe accuracy on anonymised identifier bytes  ≤  majority-class rate + margin

What the three probes do

id_positions, the gate. Trains only on the byte positions that held IP addresses and ports. If it learns anything, the anonymisation failed and the run halts.

ident, shortcut strength. Trains on the identifier fields before anonymisation, to measure what the shortcut would have been worth if left in.

ports, a named control. Measures how much of the result survives masking the port bytes specifically, separating port memorisation from payload structure.

Methodology

Padding decomposed into five input modes

8
ModeWhat the model receives
zerobyte/255 as a scalar, padding is the value 0
embeda learned embedding per byte value, padding still 0
masklearned embedding plus a distinct PAD symbol
convmaskPAD symbol, and the convolution ignores padded positions
length_balancedclasses resampled to equal length distributions

The literature changes the representation and the padding symbol together, then credits the gain to “padding-aware input”. Comparing zero → embed → mask separates the two.

The attribution this buys
  • Representation term. embed minus zero. What a learned byte embedding is worth, with the padding symbol unchanged.
  • PAD-symbol term. mask minus embed. What telling the model which bytes are padding is worth, with the representation unchanged.
  • The control. length_balanced removes length as a cue altogether, which tests whether the model was classifying content or length.

Every term is compared against the seed spread, so a difference smaller than seed noise is reported as inconclusive rather than as a finding.

Methodology

A causal early-exit classifier, so that “bytes read” is real

9

The idea. Attach classification heads at 64, 128, 256, 512 and 1024 bytes. At inference, stop at the first head whose confidence clears a threshold τ, and charge the flow only the bytes that head consumed.

exit at k = min{ k : maxc pk(c | x) ≥ τ }

Why this is not trivial. The claim only holds if head k is incapable of having seen byte k+1. Otherwise the saving is nominal and the frontier is a fiction.

Six causal dilated convolution blocks, dilations 1 to 32, kernel 5, 96 channels, receptive field 505 bytes, with left-padding only. Normalisation is per-position: ChannelNorm1d, never BatchNorm or GroupNorm, both of which average over the length axis and would let byte 900 shift the activation at byte 10.

The guarantee, and how it is held

Proposition (exit honesty). For every head k, the output depends only on bytes 1 … k. Proved by induction over the layer index, since each block is causal and the normalisation is position-local.

And tested, not just argued. tests/test_models_causality.py perturbs a byte and measures how far forward the change can reach. Measured forward reach: 505 bytes, matching the analysis exactly, and zero reach backwards.

This test is in the regression set precisely because a one-line change of normalisation layer would silently destroy the property while every accuracy number stayed plausible.

Results · Gap 1

Macro-F1 saturates at 512 bytes, and reading further is worse

13
USTC-TFC2016. Macro-F1 against byte budget, three seeds. The shaded band is the seed spread; the vertical markers are the budgets used by the twelve reviewed studies.
512 B
is the saturation budget on USTC. On ISCX it is 256 B. Every budget used by the twelve reviewed studies lies at or past that point.

And past it, accuracy falls. USTC macro-F1 goes 0.9731 at 512 B, 0.9564 at 784 B, 0.9540 at 1024 B, 0.9367 at 1500 B.

Not seed noise. McNemar's exact test on the paired 512 B against 784 B comparison finds 2488 sessions correct at 512 B but wrong at 784 B, against 94 the other way, p < 10−4.

Reading more of the flow is not a conservative choice. On this corpus it is a measurably worse one.

Results · Gap 1

Not an artefact of the architecture

14
ISCX VPN-nonVPN, two architecture families on the same store, the same split and the same seeds. Only the model changes.

An obvious objection: perhaps a 2017 convolutional network simply cannot use bytes past 512, and a modern architecture would.

We tested it. A byte transformer, self-attention over byte embeddings, replaced the convolutional stack. Everything else was held fixed.

The two families are not separable. The difference at peak is 0.0050 macro-F1 against a seed spread of 0.0379, and they saturate at the same packet budget.

Saturation is therefore a property of where the discriminative bytes lie in the flow, not of the network reading them. That is the finding that generalises.

And the failures are not the thin classes. vpn_chat has 686 test sessions and vpn_file 149, yet the 44-session vpn_email reaches 0.955 recall. A support-weighted summary would predict the opposite ordering.

Two failure modes no aggregate reports. vpn_chat is the second-largest class in the test set and the model gives it 0.042 recall: it almost never predicts the class, though when it does it is usually right. Its mirror image is vpn_file, at recall 1.000 and precision 0.241, acting as a sink for sessions the model cannot place.

And the concealment reverses sign between corpora. On ISCX the macro average flatters the model by 13 points (0.5110 against 0.3798 weighted). On USTC it understates by 1 point (0.9245 against 0.9378).

A reader who assumes a fixed relationship between macro and weighted summaries is wrong about the sign on one of the two corpora. That is the concrete form Gap 2 takes.

The padding gain is the embedding, not the padding symbol

16

Padding-aware input is routinely credited with a large gain. The decomposition shows where the gain actually comes from.

On ISCX the representation term is 28 times the PAD-symbol term, and the PAD-symbol term is well inside the seed spread, so it is reported as inconclusive rather than as a small positive effect. On USTC both terms are inside seed noise.

The practical reading: use a learned byte embedding. The explicit padding symbol, which costs extra machinery, buys nothing we can measure.

Mean bytes read per flow at τ = 0.99: 0.9659 ± 0.0113 macro-F1 against 0.9716 ± 0.0124 for the 512-byte head. The gap, 0.0058, is well inside the seed spread of either.

On ISCX the policy reads 116 bytes, 23% of 512, for 0.5134 against 0.5474, again inside the seed spread.

The comparison is honest in two ways. It is against the model's own heads, so no architectural advantage is being smuggled in; and the encoder is causal, so head k cannot have seen byte k+1. The saving is bytes genuinely not read, not a bookkeeping claim.

Results · splits

The split policy outweighs every architectural effect we measured

18
ISCX, six group-splittable classes, eight seeds. Classes, budget, model, seeds and split sizes are all held fixed. Only where the train/test boundary falls changes.
+0.38
macro-F1 from moving the train/test boundary alone. A random within-capture split scores +0.3782 over a group-wise split on otherwise identical data.

Put that next to the other effects in this talk. Changing the entire model family was worth 0.0050. Changing the padding symbol was worth 0.0086. Changing only where the split falls is worth 0.3782, seventy-five times the architecture effect.

Why it happens. A random split lets sessions from the same capture file appear in training and test, so the model can memorise capture-specific artefacts instead of learning the traffic class.

None of the twelve reviewed studies states its split policy.

Key findings

Five things we can now state with evidence

20
  • 1. The field reads 5 to 7 times more of each flow than the measurements support. Saturation is at 512 bytes on USTC and 256 on ISCX; reviewed budgets are 784 to 1024 bytes or 5 to 20 packets.
  • 2. Past saturation, reading more is measurably worse. USTC macro-F1 falls 0.9731 → 0.9367 from 512 to 1500 bytes, with McNemar at p < 10−4, because the extra bytes are mostly padding.
  • 3. Saturation is a property of the traffic, not the model. A byte transformer and a 2017 CNN are not separable on the same data, and saturate at the same packet budget.
  • 4. The padding gain is the byte embedding. The representation term is +0.2408 on ISCX; the explicit PAD symbol is +0.0086, inside seed noise.
  • 5. An adaptive reader needs 144 bytes, not 512. Macro-F1 indistinguishable from the best fixed head at 28% of the byte cost on USTC and 23% on ISCX, with a tested causality guarantee behind the number.
+0.38
And the finding that should change practice first: the train/test split alone is worth +0.3782 macro-F1, seventy-five times the architecture effect, and none of the twelve reviewed studies states its split policy.

Limitations

What we cannot conclude from this, and what could break it

21
Threats to validity
  • The receptive field is 505 bytes. It is close enough to the 512-byte saturation point that the two could be confounded on the early-exit model. The transformer control, which has no such limit and saturates at the same packet budget, is what excludes it.
  • Gap 3 is only partly answered. We report a lower bound on how much of each corpus is genuinely encrypted, not a measurement.
  • Both corpora are from 2016. A 512-byte saturation point may be a property of that cipher mix rather than of encrypted traffic generally.
Known failure cases
  • ISCX accuracy is low in absolute terms, 0.4013 uncapped. We report it rather than selecting a kinder protocol.
  • vpn_chat at 0.042 recall on 686 test sessions is a genuine failure, not a thin class.
  • The split study uses six classes, the only ones ISCX can split group-wise, so the +0.3782 carries a class-selection bias we state alongside it.
  • USTC cannot host the split study at all, because most of its classes come from a single capture file.

Conclusion

Treat the budget as a measurement, not an inheritance

22

This project took one number that the literature copies between papers and made it a measured variable. Macro-F1 saturates at 512 bytes on USTC-TFC2016 and 256 on ISCX VPN-nonVPN; every budget used by twelve recent studies lies at or past that point; on USTC reading further is significantly worse. A causal early-exit classifier comes within seed noise of the best fixed head while reading 28% and 23% of the bytes. And a random within-capture split is worth +0.3782 macro-F1, exceeding every architectural effect measured here.

Future work, following from the limitations
  • A corpus in which more classes can be split group-wise, to remove the class-selection bias from the split result.
  • A larger length-balanced subset, to turn the directional padding finding into a magnitude.
  • Pre-train the byte transformer on unlabelled captures, to test whether saturation moves once the representation is learned rather than fitted.
  • Repeat the sweep on contemporary traffic with a modern cipher mix, to see whether 512 bytes is a property of these 2016 captures or of encrypted traffic.
